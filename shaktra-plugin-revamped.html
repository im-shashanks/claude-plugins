Shaktra Plugin Revamp — v0.4.2 → v1.0.0

Context & goal

Shaktra is ~23,600 lines across 182 files. It was architected around limitations of older Claude Code, producing ~8,000 lines of orchestration prose: hand-written pseudocode loops (quality_loop, consistency_gate in tdd-pipeline.md), 29 string guard tokens matched by prefix, verbatim Task() prompt templates duplicated across 6+ orchestrator skills, sidecar-file protocols (.quality.yml, .briefing.yml, .observations.yml, .chunks/), and a dual implementation of the analyze pipeline.

Current Claude Code makes that obsolete: the Workflow tool runs deterministic JS orchestration with schema-validated agent() returns, real loops, parallel()/pipeline() fan-out, and resume; AskUserQuestion replaces prose clarification blocks; agentType references the plugin's agents/*.md directly.

Goal: clean redesign for current Claude Code only (no legacy fallbacks), same 15-command surface, quality depth preserved or improved, ~40% total size reduction (orchestration layer −65%). Plus one new shipped capability: annotatable HTML planning docs + local review server — the page you are reading is its first artifact.

  • Version 1.0.0; clean redesign, current Claude Code only
  • Analyze becomes a single Workflow-script implementation (supersedes the teams-first path)
  • HTML docs accompany canonical markdown/YAML artifacts — never replace
  • Diagrams pruned 35 → ~12

Target architecture

SKILL.md   (thin: trigger + pre-flight + AskUserQuestion + Workflow invocation + result handling)
   └─> workflows/*.js   (deterministic pipelines; real loops; schema-validated agent returns)
          └─> agents/*.md   (personas + contracts — single source, referenced via agentType)
                 └─> knowledge skills   (shaktra-tdd, shaktra-quality — untouched; the quality moat)

Escalation path (workflows cannot talk to the user):
  script returns {status: "blocked" | "needs_clarification", phase, findings|question, attempts}
  → thin SKILL presents via AskUserQuestion → re-invokes script
  → same session: Workflow resume caches completed agents
  → cross-session: handoff.completed_phases makes re-entry correct

State rule: only sequential phase agents write handoff.yml;
parallel fan-out agents are read-only — findings return in-band.

State model after revamp

  • Durable (unchanged role): .shaktra/settings.yml (single threshold source), sprints.yml, stories/*.yml, stories/<id>/handoff.yml (cross-session spine — Workflow owns in-session control flow, handoff owns cross-session truth), memory/*.yml, analysis/manifest.yml, designs/, prd.md, personas/, journeys/, incidents/

New scripts & templates

  • scripts/review_server.py (stdlib only): 127.0.0.1 + random URL token; GET doc, GET/POST/DELETE annotations (atomic writes), POST complete → flag + process exit (built & verified in Phase 0 — it is serving this page)
  • scripts/shaktra_context.py: emits one JSON context blob (settings thresholds + story + handoff + tier + memory sizing + plugin root + test_mode) — the single threshold-read point
  • templates/review-doc.html + templates/review-doc-spec.md: self-contained annotatable-doc skeleton + generation spec
  • skills/shaktra-html-review/: generate doc → background server → URL → read annotations on exit → one actionable item per annotation. Offered from tpm/pm/analyze via AskUserQuestion

Risks & open questions

  • Workflow tool availability: plugin states a minimum Claude Code version; doctor + skill pre-flights check via ToolSearch and fail with a clear "upgrade" message. Accepted per the no-fallback mandate.
  • ${CLAUDE_PLUGIN_ROOT} in scriptPath: proven for hooks, unproven for Workflow args → verified Phase 2 day one; fallback: shaktra_context.py echoes the plugin root into the context blob.
  • Parallel agents racing on handoff.yml: only sequential phase agents write handoff; fan-out agents are read-only, findings in-band.
  • E2E runtime: raised timeouts for background workflows; assertions on structured results persisted into handoff/workflow_run, not log lines.
  • Schema drift: SCHEMA_VERSION in schemas.js + repo-level CI check that validate_schema.py field lists match.
